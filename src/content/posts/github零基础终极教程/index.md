主题：这是一份假设完全没有编程基础的 GitHub 系统教程，从什么是 GitHub 讲起，经过找资源、看懂界面、分清许可证和下载方式，最后手把手创建并开源自己的第一个项目。

一、金句 之所以 GitHub 能做到上面两点，这是因为它本身就是一个所有人都可以和所有人进行分享，并且一起构建所有软件和资源的这样一个平台。

众人拾柴火焰高。

最后我鼓励大家多关注和使用开源项目，同时为开源社区贡献自己的力量。

二、分点干货 什么是 GitHub。GitHub 上可以找到最全的开源软件和资源，上面的东西做的人从一开始就打算免费给到你。比如 free programming books 这个开源项目，里面所有关于软件工程和编程的书籍都可以免费找到以及下载。大名鼎鼎的录屏和直播软件 OBS Studio 也是开源软件，可以下载它的所有版本，同时看到它的源代码，看到现在正在开发什么样的功能，以及现在面临的一些 bug 和问题，都是透明的。同类还有 3D 构图软件 Blender、音频处理软件 Audacity。AI 方面可以下载各种各样的开源大模型到自己本地进行部署和使用，以及一些 AI 软件，比如 AI 工作流生图软件 ComfyUI。除了软件还有很多学习资源，比如微软的生成式人工智能开源项目库，帮助初学者一步一步入门人工智能课程。

其次我们也可以开源自己的资源和软件，让大家一起把它构建完成和完善。作者举例自己的开源项目 open cloud control center，一开始是自用软件，后来开源了大家都能用，大家看到问题之后可以提出问题，以及一起开发和改 bug，把功能越来越完善。

在开始之前需要先去 GitHub 官网注册一个账号。来到官网点击右上角的 Sign up 也就是注册，填入邮箱、密码、用户名创建账户。注册登录之后来到 GitHub 页面，第一印象是全英文的，这里可以使用浏览器翻译插件，比如沉浸式翻译等等，把整个页面翻译成中文。教学以英文为主，这样不论选不选择翻译页面都能跟上内容。

找到好资源和开源软件一共有四种方法。

第一种是 Trending 页面。点击左上角侧边栏，打开后点击 Explore，进入 Explore 界面有很多子页面，这里只关心 Trending。Trending 统计了这一天、这一周或者这一个月最受欢迎的 GitHub 开源项目。可以改时间范围，比如改成这一周，这周最受欢迎的项目是 AI agents book，这本解释 AI agent 设计原理和工程实践的书以及配套练习代码；排名第二是 World Monitor 这样一个软件，可以实时监控整个地球上发生的所有新闻，往下拉还能看到其他受欢迎的开源项目，同样可以看这个月什么项目受欢迎。Trending 页面大家用得非常多，尤其现在有很多 AI 项目，通过它可以知道大家目前在关心什么，软件的痛点和大家需求是什么，第一时间找到最新的明星项目。

第二种是直接搜索关键词。比如知道想下载 OBS Studio 录屏软件，就搜索 obs，第一个结果就是想要的软件，点进去就可以下载。搜索本质上是对关键词的匹配，如果想按软件功能来搜索，可能搜不到最合适的结果。

第三种是问 AI。处在 AI 时代，可以让 AI 来找最合适的开源软件。比如想找一个实时语音转文字的开源软件，就可以问任何一个 AI，说推荐实时的语音转文字开源软件，AI 会去网上搜索，推荐相应项目，并说明它适合什么样的场景以及对应的特点，再从中选择一个按要求下载使用。

第四种是第三方网站和自媒体推荐。除了官方方式和 AI 推荐之外，还有很多第三方网站以及自媒体朋友做内容来推荐好的开源项目，来源还是很多的。

找到想要的项目之后进入项目页面，这个页面叫做 repository，也就是仓库，里面包含了所有的资源、所有的代码。接下来一项一项解释仓库页面的要素。

最左上角有两个名字，一个是作者的名字，第二个是项目的名字。项目名字有很多重名可能重名，加上前面作者的名字就基本上保证了项目的唯一性。以后分享开源项目的时候，告诉大家前面作者的名字和后面项目的名字，使用搜索引擎就能完整定位到唯一的项目。

往下看有好几个子页面。Code 是代码页面，Issues 是一些疑问和问题，Pull Request 是另一个。这两个在自己开源项目的时候会认真讲到，由于下载资源、使用资源基本用不到，这里先暂且不讲。

项目名字旁边有 public，public 就是公开的意思，所有人都能访问、所有人都能使用和下载。有 public 就有 private，也就是私有。GitHub 不只是用来开源项目，也可以用来保留自己私有的项目，不给别人看或者只给协作者看。作者自己的商业项目也放在 GitHub 上和别人一起协作。

往右看是三个非常重要的指标。

第一个是 Watch。Watch 的意思就是监控，点亮 Watch 之后，所有的项目动态，包括有人提的任何疑问、有新的功能被开发了等等，都会给你发通知。基本上 Watch 是项目参与者一般会点亮的指标，或者你非常喜欢这个项目的一切才会点亮，一般比较少。

第二个是 Fork。Fork 就是创建一个分支的意思，点击 Fork 之后会在自己的 GitHub 仓库里面创建一个一模一样的项目，包含所有的源代码、所有疑问、所有的开发历史。点击之后来到这个页面，owner 变成了自己，仓库名字还是不变，当然也可以给它一个新的名字。左上角作者的名字变成了自己，但后面有一个小图标，这个 Fork 分支的图标意味着这个项目实际上是从别人那里复制过来的，可以清晰看到 Fork from，这是原仓库的地址。Fork 的作用是创建一个完全一模一样的版本，由此可以在软件目前现有功能基础上再进行二次开发，添加自己想要的功能为自己所用；或者添加功能之后，还可以通过 Pull Request 合并到原来的软件里面去，让目前的项目也拥有刚才开发的功能。Fork 主要是开发者用来二次开发、复制项目用的。Watch 和 Fork 基本上都是给开发者的，想掌握一切动态就点 Watch，想复制整个代码让 AI 再进行二次开发就点 Fork。

第三个是 Star。Star 是大家听得最多的指标，意思是收藏或者点赞，有两层含义。第一层含义，点亮 Star 之后就保存了这个项目，方便以后找到。点击 Star 之后进入自己的 GitHub 页面，点击头像，再点击 Stars，就可以看到刚才收藏的项目，非常方便。第二层含义，给项目的作者点赞，给项目点赞，表示支持这个项目。Star 越多说明项目越受欢迎，看到自己喜欢的项目不要吝啬，点个赞。World Monitor 这个项目有七万五千个 Star，是非常火爆的项目。目前最火热的项目应该是 OpenClaw，现在有三十八万多的 Star。

接着往下看，有两个英文单词 Branches 分支和 Tags 标签，它们是非常重要的概念。

先看 Branches，点开下拉菜单，分支里面有很多不同的分支。首先看到 main 主要分支，它是默认分支；下面有以 fix 修复开头的分支；再往下拉可以看到以 feat、feature 特征开头的分支。

它到底是什么意思，用一个动画演示。假如在自己开发的开源项目 main 也就是默认主要分支上进行开发工作，这里面每一个绿色的点都是一次提交。提交怎么理解，就是保存一次代码，比如修了一个 bug，提交一次就保存了这次修 bug 的代码；继续又开发了一个新功能，开发完之后又提交一次，保存这次新功能的代码。依次往前推，不断开发新功能、不断修 bug、不断进行提交来保存代码。一个人这样工作没问题，可是有其他贡献者、其他开发者也想一起开发软件，总不能每次他要等我开发完，我再把代码给他，他开发完再给我，我再去开发，这样太浪费时间、太没有效率，应该能够并行开发才对，他开发他的，我开发我的，最后一起汇总，这才是正确的方式。

怎么做到，这里他就开启了一个新的分支，一个新的 Branch。另外一个开发者发现软件里的 bug，于是创建了这样一个新的分支来修登录里面的 bug，这样他就可以在新的叫做 fix login 的分支上继续工作，而这个分支在他创建的瞬间就保存了最近一个提交包含的所有修改和代码。现在他开始修 bug，与此同时我也没闲着，继续添加想要的功能。两个人分别在各自的分支上，我在 main 分支，他在 fix login 分支，都做了相应的代码修改。

现在问题来了，他把 bug 修完之后，修复只在他自己的分支上，他还想合并回 main 分支上，这样我的分支既有了自己开发的功能，也有了他的 bug 修复。这时候他就要做一次 Pull Request，也就是 PR，让大家看看，让我看看，让其他开发者看看，我修了这个 bug，能不能现在把它合并到主要的分支里面去。

这时候会出现两种情况。第一种情况，他修得很好，完全没有任何问题，这时候就可以进行合并的工作，也就是把刚才修 bug 的代码合并到目前主要的分支上来。第二种情况，他修得不好，有些问题，这时候给他建议，让他继续打磨自己的代码，这次就先拒绝，不让他合并，他需要再次修改自己的代码，之后再次进行 PR，也就是 Pull Request，再次请求合并。这样每个人都可以自己开一个分支，在自己的分支上进行开发工作。往往来说，以 fix 斜杠开头的分支是为了改一个 bug；以 feat 开头的分支是为了增加一个新的功能，因为 feat 是 feature 功能或者特性的英文简写；如果是以 docs 文档开头，就说明开这个分支是为了修改一些文档。这些不是强制的规定，是大家默认俗称的规矩。各自在各自分支上工作之后，大家都合并到 main 上面来，最终 main 分支上会包含所有新的功能和所有新的 bug 修复。Branch 分支解决了多少个人同时开发的问题。

开发着开发着往前推进，觉得这个版本已经有新功能，也比较稳定，bug 也修复了，这时候就可以进行发布，给 commit 一个额外的固定版本的名字。比如给最新的 commit 一个 Tag 标签 v2.5.23，而这个标签永远对应这个 commit。怎么理解，对于用户来说这意味着这是一个固定的版本，可以进行下载和使用。所有的版本都可以在 Tag 里面看到，点击不同的版本名称就回到当前那个版本的代码。以 2.5.23 为例，2 表示大的版本更新，后面的 5 表示一个功能的版本，23 表示修复的版本，往往是这样约定俗成的。

左边都看完了，接着往右边看。右边这个 bot 就是一句话描述项目是干什么的。往下看可以看到非常多的标签，用来告诉这个项目的类型，比如它是一个 AI 智能体项目，是一个仪表盘等。

再往下看到 Releases，就是正式发布的版本。点击一下来到正式的发布版本，首先会讲这次发布的版本有什么新的变化，解决了什么样的 bug，有什么样的新功能。可以看到 feat 开头的就是新的功能，以 fix 开头的就是一些对 bug 的修改。再往下拉就能看到用来下载相应软件的地方，根据系统不同的版本可以下载不同的安装包来安装软件。这是安装软件的方式之一，也是最简单、最直观的安装方式，比如 Mac 就安装 dmg，Windows 就安装 exe。

回到项目继续往下拉，在 README 这个网页下面，README 是非常重要的文件，是整个项目的指南针和说明书。默认 GitHub 会直接把 README 文件渲染在首页上，方便查看。由于 GitHub 上中文社区是非常强大的存在，几乎所有热门的开源项目都有中文版，大家可以第一时间来到 README 找有没有简体中文，点击进入中文页面。往下拉可以看到 README 一般包含几个部分。首先是对整个项目进行总结，它的功能都有什么，这里有截图，还有一些功能预览。然后往下往往都会包含如何快速开始，也就是如何安装软件，可以通过下载安装包进行下载，或者通过终端进行操作，通过 AI 让它帮忙安装也是可以的。往下拉会说到自己用的单独的技术栈以及一些其它信息。如果觉得 README 信息有些太宽泛，可以点击文档，看到它也专门为软件开发了一个详细文档，记录所有的功能，还有如何使用这个软件。

README 文件之外还有一个特别重要的概念，就是开源软件的证书，也就是许可证。开源软件和开源软件之间的开放程度也有区别。比如点击 License，World Monitor 其实就是 AGPL 这个证书；对应 LangChain 项目、OpenClaw，点击它的 License 看证书，就是 MIT 证书。不同证书之间有什么区别，有一个网页说明了七种常见开源许可证之间的区别，从左到右越来越严格。

首先是 MIT 证书，这可能是大家看到最常见的一种。如果软件是 MIT 证书，意味着可以把这个开源软件拿过来做任何修改，然后把它闭源变成自己的商业软件都没有任何限制，只不过要保留原来开源软件的版权声明。

再往右是 BSD-3-Clause 许可证，也是非常常见的，相比 MIT 它更进一步规定了这个开源软件做成商业软件闭源的时候，不可以用原作者来对商业软件进行背书和宣传。

再往右第三个是 Apache 2.0，再严格一点，还是可以把这个开源软件进行闭源然后商用，只不过在 BSD 的基础上还需要把开源软件的专利给讲清楚。总体来说 MIT、BSD-3-Clause、Apache 2.0 都是非常宽松的，看到这三个证书就意味着可以放心把开源项目拿过来进行修改，然后进行商用，没有任何问题。

接下来往右边看，这四个证书限制就变得多一点。首先是 MPL 2.0 证书，这个证书规定如果修改了开源软件的某一个文件，那这个文件后面也必须要开源才行，不可以闭源。下一个是 LGPL 3.0 证书，只要对这个开源项目进行了任何修改，接下来也必须要用 LGPL 继承同样的证书。第三个是 GPL 3.0 证书，就是说在用这个开源软件放到软件里面的时候，再把软件给到用户的时候，必须要提供这个开源软件部分的完整源代码。再往后是 AGPL 3.0 证书，也就是刚才看到的 World Monitor 用的证书，它可能更加严格一些，用了这个开源软件开发自己的软件，就算软件不是直接给用户，而是把它做成了一个在线的软件，大家可以登录、可以使用，就算是这种情况下，也必须要让任何在网上使用软件的用户得到这个项目的源代码。看到 MPL、LGPL、GPL 到 AGPL 这四个证书，大概就意味着这个开源项目对商业化可能有比较严格的规定。

这里需要注意，前面通过 README 知道了项目是干什么的，通过 License 证书或者许可证知道了能不能使用它以及能不能修改它，现在就是最实际的问题，怎么把项目下载并且真正使用起来。GitHub 上有常见的四种方式，分别是发布 Release、Download ZIP、克隆 Clone 和 Fork，也就是分支，它们适合的人和用途完全不同。

第一种是 Release。在项目页面往下拉，右边可以看到 Releases，点击最新的版本就可以进入下载的发布页面。往下拉会看到有不同操作系统的安装包，是 Mac、是 Windows、是 Linux，下载对应后缀的安装包就可以。Windows 下载 exe，苹果电脑下载 dmg，下载下来的就是对应的安装包，双击即可安装，跟安装其他任何软件都一样。点击 Release 可以看到很多版本，选择其中一个版本点进去，这里有 Assets，展开后可以看到各种操作系统对应的安装包，选择自己需要的下载即可。下载完成后解压安装包即可安装。一句话总结，Release 就是下载作者已经做好的成品软件，如果只是想使用这个软件，不想要二次开发，就可以直接下载 Release 里面的安装包。

第二种是 Download ZIP。点击 Code 下拉，可以看到 Download ZIP，点击它就会把整个项目的源代码打包下载到本地电脑。下载好的压缩包双击解压，打开里面就是整个项目的源代码，跟在网页上看到的一模一样。通过压缩包下载的直接就是源代码，适合分析它的代码是怎么样的，通常不能跟安装包一样双击直接安装运行，是为了临时查看文件。

第三种是 git clone。还是点击 Code，这里看到 Clone，下面给一个地址，复制这个地址。如果是 Mac 电脑就在启动台里面搜索终端然后打开，如果是 Windows 电脑就搜索 PowerShell，然后打上 git clone，粘贴刚才复制的地址就可以。如果觉得麻烦，现在有了 AI 可以不这么操作。随便打开一个熟悉的智能体，直接告诉智能体帮我克隆这个项目到本地，复制刚才的地址回车，等一会 AI 就把原项目克隆到本地。相比下载安装包到本地来保存代码，克隆不仅仅是下载了原文件，而且在电脑上建立一个真正的本地 Git 仓库。怎么理解，其实很简单，除了原文件之外，还包含了 Git 的提交历史，能看到什么时间开发了什么功能，修改了什么 bug，以及各个分支的历史。以后源代码在 GitHub 上如果有任何改变，也可以随时通过 git pull 这个命令从原仓库拉取新的提交。当然也不需要自己在终端操作，可以告诉 AI 帮我看看项目的源代码有没有更新，有的话 pull 一下，Pull 就是拉的意思，把远程最新的代码拉到本地，让本地也保持更新。git clone 非常方便把源代码放到本地之后二次进行开发。比如很喜欢这个项目，但是想要把 UI 改一下，整个界面的元素和风格改一下为自己所用，那就可以 git clone 这个项目到本地，然后让 AI 进行一些二次开发工作，适合开发和拉取更新。

第四种是 Fork。这个其实前面讲过了，就是这个按钮。相比 Clone 和下载压缩包，Fork 不是把源代码下载到本地电脑，而是先在自己的 GitHub 账号中创建一个与这个项目完全一模一样的副本，把这个项目加到自己的仓库里面去。主要用于想要修改并且参与这个开源项目，为这个开源项目做贡献。为什么需要 Fork 来参与开源项目的贡献和开发当中，因为通常没有权限直接去修改别人的仓库，原作者是他自己的仓库，但是现在通过 Fork 把原代码放到了自己的仓库。接下来可以克隆自己的仓库到本地进行任何用 AI 开发，本地开发完之后再把自己的修改推到自己远程的仓库。然后这里可以做一个 Pull Request，假设现在有了修改，自己仓库里的项目跟远程原作者的项目已经不一样了，这时候可以点击 Pull request，New pull request，把修改请求合并到原项目当中。整个过程不用担心，可以完全通过让 AI 对话来进行，让它帮你进行 Pull Request，也就是 PR，把修改请求提交到开源项目之中。

总结四种下载和使用开源项目的方式。第一种 Release，下载的是成品安装包，只适合那些想使用但不参与开发的人。第二种下载压缩包，是为了临时查看文件，因为里面包含所有源代码。第三种克隆，适合开发和拉取更新，方便自己做二次开发。第四种 Fork，是在云端创建一个一模一样的副本，适合为这个开源项目进行修改并且贡献的那些开发者。简单来说，按照目的不同，只想安装软件就在 Release 下载安装包；只想看看里面的原文件就下载压缩包；想要长期的开发和更新就使用 git clone，把原代码拉到自己本地；想要修改并且贡献这个开源项目就用 Fork 创建一个副本到自己云端仓库里面去。

讲到这里一直在受益和使用别人的项目，接下来一起开源自己的第一个项目。

第一步，建立一个空的文件夹。这里为了方便在桌面演示，大家在自己的项目文件夹里面新建一个空白的文件夹。这里仅仅是为了演示如何开源一个 Skill，同样的方法适用于任何软件项目，是网页或者其他可安装的软件都是一样的。重点不是做软件过程，而是整个开源的流程。

第二步，建立完空文件夹之后，去任何一个 AI 编程智能体来打开这个项目文件，然后做出开源项目。任何 AI 编程智能体都能完成这个工作，不需要纠结哪个，平常用得多用哪个就可以。这里新建一个项目，选中刚才新建的文件夹，然后给它一个项目的名称。

第三步，完成项目的开发。这里一起做一个 Skill，非常简单，就是把一篇文章变成知识卡片的形式。这个 Skill 用的提示词非常简单，重点不在于这个 Skill 是什么，重点是把它做完、测验完，然后把它开源出来。等一会之后 Skill 的开发就完成了。来试验一下效果，让它使用 Skill 把下面的文章转化成知识卡片。这里复制一篇保罗·格拉汉姆讲如何做自己喜欢的事情的文章给到它，可以看到它使用这个 Skill 把文章中的知识点提取出来，变成一点一点的知识卡片形式，将文章变成结构化的信息。

第四步，假设对自己这个 Skill 的效果非常满意了，就准备把它开源出来。下一步该怎么做，每个开源项目都要有这样一个 README 文件来当做说明书，告诉大家是用来干什么的、如何使用等等信息，我们的项目也不例外，要写好这个 README 文件。怎么写，当然是让 AI 写，我们来审核。这个 README 文件里面就要包含项目是为了解决什么问题的、主要的功能、安装使用的方法，以及输入输出的这样一个用例。做完了读一下 README 文件，里面就包含项目要解决什么问题、主要功能、安装的方法、项目的结构、使用方法等等信息。

第五步，有了 README 文件之后，现在要添加许可证，告诉大家可以用这个开源项目来做什么，自由度是多少。这里用最宽松的 MIT 许可证来做示范，继续告诉 AI，让它帮忙添加 MIT 证书。

接下来万事俱备了，只差最后一道工序，就是安全检查。这时候让 AI 去做这样一个工作，当然也可以自己去做，就是检查整个项目是否存在有密码或者 token 的泄露、个人的隐私、本地的绝对路径、临时文件、垃圾文件以及不该公开的内容，保证公开的项目里面没有任何隐私和不该公开的内容。这个例子非常简单，其实没什么，但是越复杂的项目大家就不要忘记做最后这一步。检查之后没有发现任何不该公开的内容。

下面开始正式开源这个项目。假设现在电脑里没有配置任何开发环境，就需要让 AI 检查有没有安装 Git，如果没有帮安装，这样方便做版本管理、提交代码等各种各样的工作。提示词就是让它检查当前电脑是否安装 Git，如果安装了显示版本号，没有安装请识别操作系统，然后帮进行安装。

既然已经安装了，继续下一步，让 AI 初始化 Git 仓库，并把默认的分支设为 main。然后准备第一个提交，这里提交就是 commit，大家现在可以简单认为保存一下代码。现在也让它做第一次提交，提交刚才开发的所有 Skill 源代码。

但是现在提交还在本地，想要开源自然是把项目放到 GitHub 仓库上去公开。这时候就需要连接 GitHub，可以自己操作，但最好是让 AI 帮助操作。这时候最好去安装 GitHub CLI，CLI 就是命令行的意思，专门用来方便 AI 来帮助做 GitHub 的操作。先让 AI 检查有没有安装 GitHub CLI，安装显示版本号，没有安装让它帮忙安装。安装好 GitHub CLI 之后，需要登录到 GitHub 账号上，然后让 AI 帮助操作 GitHub。提示词就是检查是否已经登录了，如果没有登录自己去终端登录一下。这里演示如果没有登录该怎么办，打开终端，复制 gh auth login 命令，点击回车，选择 Login with a web browser，也就是在浏览器里打开登录，选择回车，它就会打开浏览器。

登录完成之后，AI 就可以尽管给它帮操作。这里告诉 AI，请把当前的项目发布到 GitHub，先新建一个仓库的名称，然后把项目代码放到仓库里面去。告诉它可见性是 public，也就是所有人都可见，这是个开源项目；推送的分支是 main，就是现在的这个分支。等了一会之后 AI 完成了工作。去 GitHub 上看看是不是真的创建了 Skill 的开源项目，可以看到在仓库里面真的有了这样一个新的开源项目，就是刚才 Skill，成功开源了。这里有刚才看到的 README 文件，说了项目解决什么问题、功能、安装使用的方法等等信息，同时也有刚才要求的 MIT 证书列在这里。

不过右边 Release 这里没有任何正式发布的版本，现在就可以发布一个正式的版本。回到与 AI 的对话框，告诉 AI 检查当前的项目是否适合发布为 0.1.0 第一个正式版本，如果合适写一个简洁的发布说明，然后创建并推送第一个标签，第一个正式版本。第一个正式版本也发布了，去 GitHub 上看一下，刷新网页，右边中间的 Release 有了第一个版本，点进去到了发布页，输入了当前的功能，然后可以打包下载现在的源代码。当然现在没有安装包，因为这是个 Skill，所以打包下载的是自己的源代码，所有人都可以在这里下载现在版本的 Skill 为自己所用。到现在为止，第一个开源项目就创建成功了，也发布了第一个版本。

下面简单讲一下如何维护。以作者自己的开源项目为例，在分享了自己开源项目之后，很多朋友会发现项目里面还有可能多多少少存在一些 bug 和问题，这时候就可以在 Issue 这里进行留言。Open 就是目前公开还没有解决的问题，Close 就是已经解决的问题。作者举例有二十六个问题没有解决，四十一个问题已经解决。比如有朋友说在使用科研软件的时候发现群聊页面里面会出现乱码的情况，这时候就可以针对这个问题进行勘查和修 bug。这里可以给它回复，问他具体操作、系统等等环境的各方面问题，帮助定位这个问题在哪里。定位好之后可以把这个问题给到 AI，让 AI 来修复这个问题。AI 已经连到了 GitHub，能操作 GitHub 获取相关信息，就可以告诉 AI 帮我看看有没有新的 Issues，需不需要修复。新的开源项目刚开源还没有人提出问题，不过大家可以用它让 AI 帮助自己解决 Issue。

除了 Issue 之后还有 Pull Request，之前讲过，就是想要贡献给别人的开源项目，就 Fork 一下这个开源项目，自己改了之后，然后做一个 Pull Request，希望把改动汇入到原来的原始项目之中。这些就是一些开发者朋友用了软件之后，给项目做了一些开发或者修 bug 或者开发的新功能，希望把这些修改也汇入到主要的分支里面去。作者举例有十一个 Open，就十一个还没有解决的问题，二十九个已经关闭，已经解决的问题。可以让 AI 回到 AI 对话界面，帮助判断有哪些 Pull Request，有哪些值得汇入到当前的代码里面去。

到这里从什么是开源项目一路走到了自己开源第一个项目，现在就能挖到好的资源和软件，能看懂 GitHub 界面的所有元素，快速判断一个项目值不值得入，搞懂了它的工作原理，分得清七种许可证，判断这个项目能不能商用，知道四种下载使用的方式分别用在什么场景，而且已经开源了自己的第一个项目。

三、行动清单 选一个自己感兴趣的开源项目，完整走一遍四种下载方式。先在 Release 下载安装包试用，再 Download ZIP 看源代码结构，然后 git clone 到本地观察提交历史，最后试着 Fork 一份到自己账号里，对照视频里的用途体会每一种方式拿到的东西有什么区别。

浏览 choosealicense.com，对照视频里七种许可证，查自己常用软件比如 OBS Studio、Blender、Audacity、ComfyUI 的 LICENSE 文件，判断各自属于哪一类宽松或严格许可证，能不能商用、能不能修改闭源。

找一个高 Star 的热门项目，通读它 README 的标准结构，看它怎么讲问题背景、功能、安装方法、使用示例和项目结构，然后照着这个结构给自己的一个小练习项目写一份 README。

去 GitHub 官方文档 GitHub Docs 读入门章节，重点看 repositories、branches、Pull Requests、Issues、Releases 这几个概念，对照视频里的仓库页面再认一遍界面元素。

跟着一个小项目亲手练一遍 Git 基础概念：工作区、暂存区、提交历史，实际做一次 add、commit，创建一个分支，修改后再合并回主分支，建立对提交和版本的体感。

收藏几个高质量学习仓库，比如 free-programming-books-zh_CN 这类免费编程书单，以及 awesome 系列清单；筛选时按 Star 排序，再以 README 写得是否清楚、最近是否更新过作为判断标准。
